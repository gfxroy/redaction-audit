PROJECT: redaction-audit (repo name redaction-audit). One-liner: "Drop a PDF. See if its black boxes actually hide anything — and fix them for real."
Core flow: user drops a PDF (stays in browser). The app uses pdfjs-dist (worker bundled via Vite) to analyze every page and reports: "3 redactions leak text" with the recovered text shown per page, a page thumbnail with the leaking boxes outlined. One button "Fix" produces a safe PDF: pages with redactions are rasterized at 200 DPI with the boxes burned into pixels (other pages can stay vector via pdf-lib copy, but then strip their hidden text under boxes too — simplest correct approach: rasterize every page that has any dark box), metadata stripped (title/author/producer/XMP), then the app re-opens the output and verifies zero leaked text (self-check shown to the user). Download the fixed file.
Hard parts in src/lib:
1. Box detector: walk page.getOperatorList() tracking the graphics state stack (save/restore, transform/CTM, fill color in RGB/gray/CMYK, constructPath ops with rectangles and simple closed paths, fill ops) to collect filled dark rectangles (luminance < 0.2, area above a threshold) in page user space. Also detect black highlight/square annotations (getAnnotations: Square, Highlight, Redact that is not applied) and treat them as covers.
2. Text geometry: page.getTextContent() items -> glyph-level approximate boxes (split each item width proportionally by characters) in the same coordinate space.
3. Intersection: a character "leaks" if >50% of its box is covered by a dark box drawn AFTER the text, or any cover at all for annotations; group leaked characters into strings per box. Handle rotation/viewport. Also flag white boxes covering text (whiteout).
4. Fixer as described, with self-verification.
Include a sample "bad redaction" PDF generated by a script with pdf-lib (text drawn then black rectangles drawn on top) committed under public/samples/ plus a "Try a sample" button, and a correctly-redacted sample to show the green-path (rendered as monochrome "No leaks found").
UI: one large drop zone ("Drop a PDF"), results list, Fix button, download. Monochrome only; leaking text shown in a mono font on #171717.
Tests: unit tests for the geometry/intersection, the operator-list walker using synthetic operator lists, and an end-to-end node test that runs pdfjs (legacy build) on the generated bad sample and finds the leaked strings, then runs the fixer and verifies no text remains (if node canvas is unavailable for rasterization, test the detector end-to-end and the fixer with a mocked rasterizer).
